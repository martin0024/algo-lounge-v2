## Lemonade Change

**Algorithm:**

1. Keep running counters of `$5` and `$10` bills on hand (we never give `$20` as change)
2. For a `$5` customer: just take the bill
3. For a `$10` customer: need one `$5` back. Fail if we don't have one
4. For a `$20` customer: need `$15` back. Prefer giving one `$10` + one `$5` over three `$5` bills
5. If we can't make change for any customer, return `false`

**Time Complexity:** O(n) — single pass over `bills`

**Space Complexity:** O(1) — only two counters

**Key Insights:**

- Greedy choice on the `$20` customer: use a `$10` + `$5` first, saving the `$5`s for future `$10` customers who *must* be paid in `$5`
- Hoarding `$5`s is always at least as good as any alternative

```python
def lemonade_change(bills):
    five = 0
    ten = 0
    for bill in bills:
        if bill == 5:
            five += 1
        elif bill == 10:
            if five == 0:
                return False
            five -= 1
            ten += 1
        else:
            if ten > 0 and five > 0:
                ten -= 1
                five -= 1
            elif five >= 3:
                five -= 3
            else:
                return False
    return True
```
