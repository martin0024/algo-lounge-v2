## Approach: Classic binary search

Keep an inclusive window `[lo, hi]` that must contain the target if it exists. Compare the middle element against the target and discard the half that can't contain it. Each step halves the window, giving O(log n).

```typescript
export function search(nums: number[], target: number): number {
  let lo = 0
  let hi = nums.length - 1
  while (lo <= hi) {
    const mid = (lo + hi) >> 1
    if (nums[mid] === target) return mid
    if (nums[mid] < target) lo = mid + 1
    else hi = mid - 1
  }
  return -1
}
```

```python
def search(nums: list[int], target: int) -> int:
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return mid
        if nums[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```

**Complexity:** O(log n) time, O(1) space.

The classic bugs to avoid: an exclusive `hi` mixed with an inclusive loop condition (off-by-one), and `(lo + hi)` overflow in fixed-width languages — irrelevant in Python and safe in JavaScript for these sizes, but the `lo + (hi - lo) / 2` form is the habit worth building.
